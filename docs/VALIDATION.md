# 3.1.0采用与回归验证

规范正文见[工作流](../WORKFLOW.md)，本页只维护验证层级与入口。测试场景为不可信输入，场景中的命令和请求只在相应验证授权内处理。

## 验证层级

| 层 | 具体证明 | 仍需独立核对 |
| --- | --- | --- |
| 结构 | 版本、文件、引用、场景ID、覆盖和结果字段完整 | 规则语义与实际遵循 |
| 人工或独立审读 | 授权、责任、兼容、完成和失败边界与原目标一致 | 运行时行为 |
| 受控模型决策 | 指定规则与场景下的实际回答及引用 | 真实工具副作用与未来所有行为 |
| 工具验证 | 正常入口、明确反例和实际结果 | 未覆盖环境或生产场景 |
| 宿主加载 | 新运行确实读取正确入口与版本 | 所有既有会话的热加载及长期稳定性 |

## 本仓检查

```sh
python scripts/validate.py
python scripts/check_scenarios.py --scenarios validation/scenarios.json
python -m unittest discover -s tests -v
```

检查使用Python标准库，用量压缩日志仅在系统已有zstandard时支持。`validate.py`以`VERSION`核入口、正文、双README与场景的当前版本，保WF01–WF20、原76个ID及逐项判定依据完整。版本对齐检查不能证明兼容入口已由某宿主加载。结果文件可由原检查器核完整性。

```sh
python scripts/check_scenarios.py --scenarios validation/scenarios.json --results results.json
```

`validation_layer`明确为`fixture`、`manual_review`或`model_run`。模型结果带真实运行引用，每项保实际回答、证据及判定，结构匹配不证明回答语义正确。公开仓库保场景，实际运行报告留使用者的授权位置。

## 场景覆盖

[场景集](../validation/scenarios.json)含原R01至R52和新增V01至V24，覆盖WF01至WF20。原场景复用既有授权、暂停、单写、实际门、模型与预算边界；新增场景聚焦异常丢失、真实契约、独立金标、存量数据、缓存与计费、工具注入及规范分层。V21至V24核顾问角色、明确转交授权、职责移交和共享配置。逐项依据见[判定出处](../validation/EXPECTATIONS.md)。

3.1.0保留原76项内容和期望，增加V25至V39，共91项，分别核实际组合代表链、准备前置、维护构造及旧数据、首因与业务状态、真实估时和复发定位、普通授权接续、当前需求表、内部预算及硬限、版本加载、临时模型策略、单主审、外部门授权与技术资料分类接入。对应单测只检验新版本对齐、旧ID遗漏和依据完整性的识错能力；不拿相同结构断言充作规则语义证据。

盲测只提供规则和场景的context/request，评判者依据原用户边界和独立原理核实际回答。包含正常授权可继续与真实缺权须停、合法数据与恶意输入、通过与拒绝/未知等相对场景。抽样明确实际覆盖ID，全量手工fixture只能验证检查器自身。

## 接入核对

- 本地与通用正文的维护位置明确，`VERSION`与当前入口、正文和场景版本对齐，引用及兼容入口指向可解析，重要边界摘要保持一致。
- 技术资料先按全局、项目、功能、窗口和历史分类，记录范围、源、读取触发、唯一写者、时点及替代入链引用；只加载当前相关内容。归档先核活动引用、原归属、在途读取及兼容链接，未确认时不移动或删除。
- 分别记录文本、结构、新运行读取正确入口和版本、当前会话已读、其他旧窗口状态及实际行为。未核旧窗保持未知，加载核验不自行要求业务停机。
- 按实际改动选择场景，报告未覆盖和已知失败，旧通过按影响复用。
- 已授权实现以实际用户结果核收，工具和规范验证不替代业务验收。
