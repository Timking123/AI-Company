## 一手方法来源

- S01 [Pact: How Pact works](https://docs.pact.io/getting_started/how_pact_works)，定位于Consumer testing, Provider verification, Non-HTTP testing。双向契约方法，message pact替代MQ，不能证明真实broker或完整业务入口。
- S02 [SQLite: How SQLite Is Tested](https://sqlite.org/testing.html)，定位于§2 Test Harnesses, §3 Anomaly Testing, §7.6 Mutation testing。支持独立判定、差分及识错能力，不把其测试规模和覆盖率移植为每任务硬门。
- S03 [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)，定位于Outcome定义, Types of graders, research/computer-use agents, Step 3–5。结果状态、评分器能力和环境需分别核证，工程建议不构成通用可靠性保证。
- S04 [UK AISI Inspect: Log Files](https://inspect.aisi.org.uk/eval-logs.html)，定位于EvalLog status/error/results/samples, Eval Retries。评测执行状态与样本评分分开，不将特定框架字段强加给所有宿主。
- S05 [Holistic Agent Leaderboard: The Missing Infrastructure for AI Agent Evaluation](https://arxiv.org/html/2510.11977v1)，定位于§4.2, Appendices A3, A4, A5。基础设施、泄漏和成本可影响测量，行为相关性不能直接解释为因果收益。
- S06 [gRPC: Deadlines](https://grpc.io/docs/guides/deadlines/)，定位于Deadlines on the Server, Deadline Propagation。传播剩余期限、处理时钟偏差，应用仍负责停止其派生工作。
- S07 [Anthropic: How we built our multi-agent research system](https://www.anthropic.com/research/multi-agent-research-system)，定位于Benefits, Prompt engineering, Production reliability。成本与收益是特定研究系统的观测，不支持默认多代理或降低用户容量要求。
- S08 [AWS: Timeouts, retries, and backoff with jitter](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)，定位于Introduction, Retries。超时不证明无副作用，重试考虑幂等、层级与次数，不自动提供重试授权。
- S09 [DORA: Working in small batches](https://dora.dev/capabilities/working-in-small-batches/)，定位于How to work in small batches, INVEST。支持独立、有价值、可测试的短批，不是删除既有功能或跳门的理由。
- S10 [Go standard library: context](https://pkg.go.dev/context#Cause)，定位于Cause, WithCancelCause, CancelFunc。取消原因可独立保留，取消调用不等待工作停止，具体接口属于Go。
- S11 [SWE-bench maintainer discussion #267](https://github.com/SWE-bench/SWE-bench/issues/267)，定位于2024-12-09运行输出与最终报告, 2026-08-14关闭说明。历史案例支持校准环境与评分器，不证明当前版本仍存在原缺陷。
- S12 [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents)，定位于When (and when not) to use agents, When and how to use frameworks。简单可组合流程优先，复杂度按实际收益增加，不构成用户授权来源。
